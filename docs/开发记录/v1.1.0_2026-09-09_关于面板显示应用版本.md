## 2. 任务目标

应用此前没有任何地方显示自己的版本：`README.md` 顶部写着 v1.0.0，但界面、接口、日志里都查不到，用户报障时无法说明白"我跑的是哪一版"，`.qoder/agents/version-release.md` 打 tag 时也只能靠人读 README。

本次迭代要求：**界面能自动显示版本号**，且**不得引入第二份需要人工同步的版本号副本**——README 仍是唯一来源，多处手工同步从"靠纪律"变成"机器可校验的契约"。

## 3. 问题诊断与分析

**问题 1：版本号放进哪里，才不会和文档说的不一致。**
现象：本项目已有两处版本号载体（README 顶部版本行、README 第 9 节版本历史），再加上 `docs/开发记录/index.md` 与迭代记录文件名，一次发布共 4 处手写。
原因：如果为了显示方便再在代码里加一个 `VERSION = "1.1.0"` 常量或 `VERSION` 文件，就变成第 5 处；而 `app/config.py:Settings` 是 `.env` 驱动的、`app/settings_store.py:SettingsPatch` 是"运行时可改"的白名单，把版本号放进去等于向用户宣告"这个值可以在界面上改"——改完 `README.md` 不会跟着变，界面显示的版本立刻成为谎言，且没有任何机制能发现。

**问题 2：读文件这件事不能把 `/api/about` 打挂。**
现象：`/api/about` 是侧边栏「关于」面板渲染的唯一数据来源；该面板是用户排障（版本、runtime、模型体积）的入口。
原因：一旦版本号来自文件读取，就多出三类新失败：README.md 不存在（只部署 `app/` + `static/` 的裁剪包）、编码非 UTF-8（被别的编辑器另存过）、版本行被人手改成不认识的形状。任何一类若抛异常，端点 500，面板连 runtime 状态都画不出来——恰好在最需要看它的时候失效。

**问题 3：改 README 版本号后，界面何时反映。**
现象：`run.py` 里 `uvicorn.run("app.main:app", ...)` **没有** `reload=True`，Python 侧改动必须重启；但 README 是数据文件而不是代码。
原因：若每次请求都重新读盘 + 正则，`/api/about` 会为一个小字符串做全文 IO；若读一次就缓死在模块变量里，则改 README 必须重启，"免重启生效"这个卖点就成了空话。

**问题 4：契约成立之后，谁能保证它一直成立。**
现象：`app/version.py` 的正则与 README 那一行互为依赖，但两者都在被不同的人（作者手改、`iteration-doc` 生成、`version-release` 读取）编辑。
原因：文档约定不受任何编译期或测试期保护。正则写成 `：`（全角冒号）匹配不到 README 的半角 `:`，返回值静默为 `None`，界面只显示"未知"——不会崩，也就不会有人去查。

## 4. 解决方案与实施

**核心原则**：文档里的数字是被显示的那一个；显示逻辑不拥有版本号，只消费它；凡手工同步的地方一律配上机器校验。

### 4.1 变更表

| 文件 | 变更 | 说明 |
|---|---|---|
| `app/version.py`（新增） | `read_version(readme: Path = README) -> str \| None` | 用 `VERSION_RE = re.compile(r"\*\*版本 / Version\*\*:\s*v(\d+\.\d+\.\d+)")` 在 README 正文中搜索，返回**不带 `v` 的**裸版本号（如 `"1.1.0"`） |
| 同上 | 模块级 `_cache: tuple[tuple[str, int, int], str \| None] \| None` | 缓存键是 `(str(path), st_mtime_ns, st_size)`，README 被编辑后 mtime_ns 变化即自动失效，故改版本号无需重启；`/api/about` 在事件循环线程内是单线程访问，元组整体替换无需加锁 |
| 同上 | `_log_unreadable(readme, why="unreadable")` | 三条失败路径（`stat()` 抛 `OSError`、读文本抛 `OSError`/`UnicodeDecodeError`、正则不匹配）统一走 `log.warning` 一次并把 `None` 写进缓存，**函数不抛异常**；缺失的 README 不会每个请求刷一行日志 |
| 同上 | `ROOT = Path(__file__).resolve().parent.parent`、`README = ROOT / "README.md"` | 参数是普通 `Path` 且**不 import 本包任何其他模块**，测试可以指向临时目录里的假 README |
| `app/main.py` | `from .version import read_version`；`about()` 响应字典**首位**插入 `"version": read_version()` | 取不到时是 `null` 而不是缺字段，沿用 `SystemStats` 的约定（前端靠字段存在与否区分"未知"与"接口没这个键"） |
| `static/app.js` | `loadAbout()` 的 `rows` 数组首位插入 `["应用版本", a.version ? \`v${a.version}\` : "未知（未能从 README.md 读到版本行）"]` | `v` 前缀只在前端拼，接口回传裸数字；排第一行是因为它正是报障时被引用那句 |
| `tests/test_version.py`（新增） | 11 个用例，分三类 | 见 4.3 |
| `README.md` | 顶部版本行 v1.0.0 → v1.1.0；第 3 节 `app/` 模块数 14 → 15（补 `version.py` 一行）、`tests/` 8 → 9 个文件；第 5 节 `/api/about` 行补"应用版本"；第 6 节用例数 455 → 466；第 8 节新增一条"版本行格式是契约"；第 9 节新增 v1.1.0 条目 | 第 3/5/6 节属于本次迭代使事实失真的必要订正，未顺手重写其他章节 |
| `docs/开发记录/index.md` | 记录列表顶部追加 v1.1.0 条目（含基线短哈希） | — |
| `.qoder/agents/iteration-doc.md`、`.qoder/agents/version-release.md` | 凡"取版本号一律 Grep README"的规则改为以 `read_version()` 为准，并说明格式已被测试锁定 | 见 7 技术栈之后「经验教训」第 6 条 |

### 4.2 关键取舍

| 备选方案 | 未采用原因 |
|---|---|
| 代码里放 `VERSION = "1.1.0"` 常量 | 成为第 5 处手工同步点；常量与 README 可以**静默不一致**，界面就会显示一个没有任何文档声称过的版本 |
| 独立的 `VERSION` / `version.txt` 文件 | 只是把副本挪了个位置，README 仍要手抄一遍；且它比 README 更容易在打包/裁剪部署时被漏掉 |
| 做成 `Settings` 字段（`APP_VERSION`） | 语义错误：`Settings` 的值来自 `.env` 且可被 `settings_override.json` 覆盖，等于允许用户把版本改成任意字符串；还会连带要求 `.env.example` 说明与 `EDITABLE` 决策，扩大"运行时可改"白名单的承诺面 |
| `git describe --tags` | `.venv/Scripts/python.exe` 起的服务不保证能调到 `git`；发布时用户可能持有 README 尚未更新的中间提交，`git describe` 会给出 `v1.0.0-8-gc8674b5` 这类与文档对不上的串；另外会让 `app/` 依赖 `.git` 存在，裁剪部署即失效 |
| 构建期生成 `app/_version.py` | 本项目**没有构建步骤**（前端是免构建原生三件套），为此引入 codegen 与红线冲突 |

### 4.3 缓存与失效的实际行为

`_cache` 键含 `str(path)`，因此临时目录里的测试 README 绝不可能命中仓库 README 留下的缓存项——这是跨用例污染的唯一入口，已在 `test_cache_follows_an_edit_without_a_restart` 中用 `os.utime(path, ns=...)` 钉住时间戳验证（同一 mtime tick 内的原地改写是这类缓存的经典漏网场景，不能信任时钟粒度）。

### 4.4 测试设计（`tests/test_version.py`，11 用例）

- **`ReadFromReadme`（5）**：README 能解析出 `X.Y.Z`；默认参数与显式 `README` 结果一致（防止工作目录漂移取到旧副本）；文件缺失返回 `None` 且 `assertLogs("app.version", "WARNING")` 命中；三种坏形状（全角冒号 `**版本 / Version**：v1.2.0`、缺修订号 `**Version**: v1.2`、纯文本 `版本 v1.2.0`）在 `subTest` 下逐个返回 `None` 并告警；mtime 变化后取到新值。
- **`ReleaseStaysSynchronised`（4）**：README 版本行 == README 第 9 节首条 `### vX.Y.Z` == `docs/开发记录/index.md` 记录列表首条 `- vX.Y.Z `；已有迭代记录时最新记录文件名的版本 == README 版本（当前无记录时 `skipTest("no iteration record exists yet")`）；所有 `v*.md` 文件名符合 `vX.Y.Z_YYYY-MM-DD_描述.md`。
- **`WireContract`（2）**：`app/main.py` 中 `/api/about` 函数体含 `"version": read_version()`（源码断言，而非发请求）；`static/app.js` 含 `a.version ? \`v${a.version}\``，即前端不得把 `v` 混进对账值。
- 模式常量在本文件内**独立重写一份**（`README_VERSION_RE` 等），与 `app/version.py` 的不共用——两处若哪天不再等价，本文件应报错而不是和实现一起自洽地错。全部按正则读取，不按行号取，因为周围正文会随每次发布变长。

## 7. 经验教训

1. **为什么读 README，而不是常量 / `VERSION` 文件 / `git describe`**：判据不是"哪种更优雅"，而是"哪一种能让显示的版本谎报而不被发现"。代码常量与 `VERSION` 文件都会制造第二份真相，二者不一致时没有任何信号，界面照旧自信地渲染错值；`git describe` 把答案绑在仓库状态上——服务进程不保证调得到 `git`、裁剪部署时 `.git` 可能不存在，而它给出的 `v1.0.0-8-gxxxx` 与 README 声称的版本天然不同。README 是本项目已承诺的**版本号唯一来源**（第 8 节），让运行时反过来读它，等于把"两份真相"折叠成一份：显示的、文档写的、tag 打的必然是同一个字符串。代价是那行文本从排版变成了契约，于是需要第 4 条。
2. **配置对象的边界**：`Settings` 表达"可由部署者配置"，`SettingsPatch` 的白名单进一步表达"可在运行时被界面改"。版本号两者都不是。判断准则可以直接复用到下次迭代：**一个值若不该出现在 `.env.example` 的说明里，它就不该是 `Settings` 字段**——`version` 显然不该。
3. **容错的形状是 `null` 而非缺字段**：`/api/about` 一旦可能因读盘失败而整体 500，失去的是整个排障面板。因此取不到版本时"这个键仍在，值为 `null`"，前端才有区分"未知"与"接口尚未提供该字段"的依据；这条约定写进了 `WireContract`。同时把告警**收敛到每次文件变化一次**（结果连同 `None` 进缓存），否则永久缺失的 README 会每个请求刷一行日志。
4. **版本号进入运行时后，文档格式就成了契约**：这不是隐喻，而是两处具体的脆弱点——(a) `app/version.py:VERSION_RE` 与 README 那一行必须等价，全角冒号/漏 `**`/少一位补丁号都会让它返回 `None`；(b) 四处手写落点必须报同一个版本。解法是各配一个测试：`ReadFromReadme` 盯 (a)，`ReleaseStaysSynchronised` 盯 (b)。此后 `iteration-doc` 若漏同步第 4 处，CI 化跑测试即在"发布"这一步之前失败，而不是等人对着界面发现。附带教训：断言文档时**按正则取，不按行号取**——正文每次发布都在变长，按行号写的断言活不过下一次迭代。
5. **mtime 缓存的两个坑**：原地改写可能落在上一次 `stat()` 记下的同一个 mtime tick 内，测试必须 `os.utime(ns=...)` 钉住时间戳，不能信任时钟粒度；缓存键必须含路径本身，否则临时目录的测试 README 会命中仓库 README 的缓存项，表现为"某个用例单独跑能过、全量跑随机失败"。
6. **规则文档也是本次改动的一部分**：`app/version.py` 立起机器可读入口后，`.qoder/agents/version-release.md` 第 3 节"用 `Grep` 在 README 匹配版本行"就不再是最佳取法（它对格式无感知，而 `read_version()` 是界面实际显示的那个函数），已改为优先调 `read_version()`、Grep 作对账；`iteration-doc.md` 里写死的 455 用例数也按红线第 6 条改为"以命令末行 `Ran N tests` 为准"。历史文档条目（含 v1.0.0 那条）一律不回改。
7. **工具链踩坑**：PowerShell 5.1 下 `python -m unittest ... 2>&1 | Select-Object` 会把 unittest 写到 stderr 的正常进度当成错误记录（`NativeCommandError`），甚至可能让退出码变 1 而测试其实 `OK`。判定成功请以末行 `OK` 为准，或单独读 `$LASTEXITCODE`，不要因为红色输出误判失败。本次采用 `*> runtime\xxx.log; "exit=$LASTEXITCODE"` 的写法：全量重定向到 `runtime/`（不入库）再取尾行，退出码干净可靠。
8. **`/api/about` 无法在请求上下文外直接调**：本次想用临时脚本跑一次端到端验证，第一版 `await main.about()` 直接 `AssertionError`——`app/main.py:about()` 开头的 `assert runtime is not None` 依赖 lifespan 里创建的全局 `runtime`，也就是说这个端点**只有在完整启动（含 llama-server 子进程）后才可读**。要给未来的 `tests/test_*.py` 加接口级断言，得先能注入假的 runtime（目前 `app/main.py` 没有这个接缝，而为此改构造方式不属本次范围）；本次退而验证"两头"（`read_version()` 不抛 + `JSONResponse` 保留 `null` 键），已足够支撑结论，记录里也这么写而不夸大为端到端。

## 11. 总结

本次迭代让应用第一次知道自己是哪一版：新增 `app/version.py:read_version()` 按正则从 `README.md` 的版本行取号并按 `(路径, mtime_ns, size)` 缓存，`/api/about` 带出 `version` 字段（取不到即 `null`，绝不 500），侧边栏「关于」面板首行显示「应用版本」，`v` 前缀只在前端拼以保持接口值可与 `git tag` 直接对账。版本号刻意不做成 `Settings` 字段，避免把"不可配置的值"塞进 `.env` 与运行时可改白名单。更重要的收益是把原先依赖纪律的 4 处手工同步升级为契约：`tests/test_version.py` 的 11 个用例既盯"README 版本行 ↔ 正则"的格式一致性，也盯四处落点报同一个版本，还盯 `/api/about` 的字段与前端不重复拼前缀；文档格式自此受测试保护。配套校正了 `.qoder/agents/iteration-doc.md` 与 `version-release.md` 中取版本号的规则，并订正 README 因本次改动而失真的第 3、5、6、8、9 节。
